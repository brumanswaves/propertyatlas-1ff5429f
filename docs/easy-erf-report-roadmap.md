# Easy Erf Report North Star

Easy Erf is a living, evidence-backed property intelligence system — not a static PDF and not a generic property portal.

## Product target

Every report must help the user answer:

1. Is this the correct property?
2. What is known and where did it come from?
3. What remains missing, uncertain, or contradictory?
4. What are the material risks and opportunities?
5. What should the user do next?

Every claim must be one of:

- official evidence
- uploaded evidence
- user-confirmed information
- deterministic calculation
- clearly labelled AI interpretation
- assumption
- unknown / missing

## Locked delivery path

### Phase 1 — Report foundation

- Premium living report shell
- Decision-readiness categories
- Identity, ownership, planning, market, risk, Site Potential, strategy, documents, recommendations
- Print / Save PDF foundation

### Phase 2 — Intelligent report

- Executive Decision Brief
- Evidence engine
- Transparent Property IQ / confidence categories
- Contradiction detection
- Missing information engine
- Grounded recommendations
- Decision matrix
- Evidence timeline
- Ask Easy Erf grounded only in saved property evidence
- Report change tracking foundation

### Phase 3 — Easy Erf AI

Property-specific questions answered only from the property evidence set, with evidence references and uncertainty labels.

### Phase 4 — Decision modes

- Investor
- Developer
- Renovator
- Family
- Rental
- Retirement
- Commercial

### Phase 5 — Property Digital Twin

A permanent property intelligence record containing documents, reports, valuations, inspections, market evidence, images, concepts, quotes, contractors, conversations, decisions, and changes over time.

## Development rules

1. Codex/GitHub performs implementation, testing, refactoring, and PR work.
2. Lovable is reserved for visual refinement, previewing, runtime configuration, and publishing.
3. No fabricated property facts or unexplained scores.
4. Every AI conclusion must show its evidence and uncertainty.
5. Every screen must make the next action obvious.
6. Simple first; expert depth underneath.
7. New features must advance the property intelligence north star.

## Phase 2 protected boundaries

Do not change:

- map or CSG/Kouga loaders
- Site Potential generation pipeline
- Local Services backend
- Supabase schema or migrations
- authentication
- package.json
- bun.lock
- src/routeTree.gen.ts
- Production deployment
