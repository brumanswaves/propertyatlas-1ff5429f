# ErfStop Codebase Audit

Audit date: 2026-06-19  
Scope: full local repository inspection. No application code was edited.

## 1. Architecture and Framework

ErfStop is a React 19 + TypeScript single-page/SSR-capable application built with TanStack Start, TanStack Router, Vite, Tailwind CSS 4, shadcn/Radix UI primitives, Mapbox GL JS, React Query, Supabase, and Lovable Cloud helpers.

Key architectural layers:

- `src/routes/*`: file-based TanStack Router routes.
- `src/components/layout/*`: top nav, footer, marketing/legal wrappers.
- `src/components/map/*`: Mapbox map, layer controls, filtering, legend, search.
- `src/components/property/*`: demo property panel, official parcel panel, saved links, tabbed research workspace.
- `src/lib/providers/*`: provider abstraction, demo provider, ArcGIS/public-data clients, readiness/stubs.
- `src/integrations/supabase/*`: generated Supabase clients, auth middleware/attacher, generated DB types.
- `supabase/migrations/*`: app database schema and RLS policies.
- `supabase/functions/arcgis-public-proxy/*`: deployed Edge Function proxy for ArcGIS endpoints.
- `public/data/*`: test-only GeoJSON fixtures. Expected official static fallback files are referenced but not present.

The app has two overlapping data models:

- Demo parcel intelligence: generated in-memory synthetic parcels from `src/data/properties.ts`.
- Official public map overlays: live/fallback CSG and Kouga ArcGIS data loaded into Mapbox sources.

That split is currently the most important product and technical fact in the repo. Official parcel clicks open `OfficialParcelPanel`, while rich valuation/ownership/tabs open only for demo parcels.

Routes are generated by TanStack Router in `src/routeTree.gen.ts`.

- `/reports`
- `/data-sources`
- `/faq`
- `/contact`
- `/privacy`
- `/terms`
- `/disclaimer`

Application/account routes:

- `/auth`: email/password and Google sign-in.
- `/dashboard`: saved properties, notes count, saved listings, report interests.

Admin/diagnostic routes:

- `/admin`
- `/admin/readiness`
- `/admin/public-data-debug`

Important route behavior:

- `/` reads `?parcel=<id>` from `window.location.search` on mount and opens a demo parcel only if `getProperty(parcel)` exists.
- Saved-property links on `/dashboard` navigate to `/` but do not include the parcel query, so they do not reopen the saved parcel.
- `/admin/public-data-debug` is publicly routeable in the route tree. Any access control would have to be inside the route/component; none was obvious in the inspected file.

## 3. Map Implementation

The main map is `src/components/map/MapCanvas.tsx`, using Mapbox GL JS.

Map sources:

- `parcels`: demo synthetic parcel polygons from `propertiesToGeoJSON(PROPERTIES)`.
- `parcel-centroids`: demo centroids used for heatmaps.
- `csg-parcels`: official/live/imported/test CSG GeoJSON source.
- `kouga-zoning`: official/live/imported/test Kouga zoning GeoJSON source.

Map layers:

- Demo parcel fill, outline, hover glow, zoning layer.
- Demo heatmaps for investor, development, ocean view, appreciation, rental, long-held, seller probability.
- CSG official fill/outline/glow.
- Kouga zoning fill/outline.

Default home behavior:

- `DEFAULT_LAYERS` determines whether demo parcels or official layers are initially visible.
- Public copy strongly implies official public data mode: "Zoom in and click a CSG parcel."
- Demo mode is hidden from normal UI and restored only from `localStorage` (`pa.demoMode`).
- Test geometry can be enabled only through `/admin/public-data-debug` via `pa.testGeometry`.

Interactivity:

- Demo parcel clicks are registered on `parcels-fill` and call `onSelect(id)`.
- CSG clicks are registered on `csg-parcels-fill` and call `onSelectOfficial(...)`.
- Kouga clicks are registered on `kouga-zoning-fill` and call `onSelectOfficial(...)`.
- Demo double-click fits bounds for the clicked demo polygon.
- Selection state is maintained with Mapbox feature state using promoted `id`.

Resilience:

- The map checks WebGL support and shows a retry overlay on WebGL context loss.
- Style switches re-run source/layer setup through `styleVersion`.
- Public-data layers are reloaded on `moveend`.

## 4. Parcel Loading Pipeline

There are two separate parcel pipelines.

### Demo Parcel Pipeline

1. `src/data/properties.ts` generates a synthetic St Francis Bay pilot cadastre at module load.
2. `PROPERTIES` is converted into GeoJSON for polygon and centroid sources.
3. `MapCanvas` adds the sources and layers.
4. Search/filtering operate entirely on the in-memory `PROPERTIES` array.
5. Clicking a demo parcel selects `parcel-N`.
6. `src/routes/index.tsx` resolves the selected id with `getProperty(selectedId)`.
7. `PropertyPanel` renders valuation, ownership, sales, intelligence, research, listings, reports, notes, and calculators for that demo property.

### Official Public Data Pipeline

1. Home map toggles `csgParcels` and/or `kougaZoning`.
2. `MapCanvas` checks zoom thresholds:
   - CSG requires zoom >= 13.5.
   - Kouga requires zoom >= 11.5.
3. It builds the current bbox from `map.getBounds()`.
4. It calls `loadOfficialPublicLayer(layer, bbox, 400)` in `src/lib/providers/publicDataClient.ts`.
5. The fallback chain is:
   - Direct browser ArcGIS fetch.
   - Supabase Edge Function `/functions/v1/arcgis-public-proxy`.
   - Static imported official GeoJSON.
   - Empty official-link-only result.
6. If admin test geometry is enabled, test fixtures may be loaded after official sources fail/return empty.
7. Returned features are set on the Mapbox source.
8. Clicking CSG/Kouga opens `OfficialParcelPanel`, not the rich `PropertyPanel`.

Important gap:

- The client references `/data/st-francis-csg-parcels.geojson` and `/data/kouga-zoning.geojson`, but `public/data` only contains `test-csg-parcels.geojson` and `test-kouga-zoning.geojson`. Static official fallback is therefore missing.

## 5. Supabase Integration

Supabase is used for authentication and user-owned workspace data. It is not currently the authoritative parcel geometry source.

Client integration:

- `src/integrations/supabase/client.ts` creates a browser/SSR-aware Supabase client from:
  - `VITE_SUPABASE_URL` or `SUPABASE_URL`
  - `VITE_SUPABASE_PUBLISHABLE_KEY` or `SUPABASE_PUBLISHABLE_KEY`
- The app throws during lazy client creation if those env vars are missing.
- `src/lib/auth/useAuth.tsx` subscribes to `onAuthStateChange` and calls `getSession()`.

Server/admin integration:

- `src/integrations/supabase/client.server.ts` creates a service-role client from `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`.
- `src/start.ts` installs `attachSupabaseAuth` as function middleware.

Database tables:

- `profiles`
- `saved_properties`
- `watchlists`
- `user_roles`
- `report_orders`
- `property_listings`
- `property_notes`
- `property_research_links`
- `provider_cache`
- `provider_audit_log`
- `provider_settings`

RLS posture:

- User-owned tables generally use `auth.uid() = user_id`.
- `profiles` uses `auth.uid() = id`.
- Admin access relies on `public.has_role(auth.uid(), 'admin')`.
- `provider_cache` and `provider_settings` are intended to be admin-readable, but broad grants plus restrictive RLS should be reviewed in a real Supabase project.

Notable Supabase risks:

- Some component queries filter only by `parcel_id`, not by `user_id`. RLS should still enforce ownership, but explicit `user_id` filters would reduce ambiguity and wasted scans.
- `ReportsTab` inserts `provider: "placeholder"` into `report_orders`, while later migrations constrain/derive `provider_id` from known provider enums. This may create inconsistent legacy text status/provider values.
- Report interests are partly stored in `localStorage`, so dashboard counts are per-device, not truly account-backed.

## 6. Why Parcels May Not Be Clickable

Likely causes:

1. Official layers are not loaded because zoom is below threshold.
   - CSG does not fetch until zoom 13.5.
   - Kouga does not fetch until zoom 11.5.

2. Official endpoints return zero features, fail CORS, rate-limit, or time out.
   - The fallback chain may end in an empty source.
   - The UI then shows "No CSG parcels in this view" or unavailable messages.

3. Static official fallback files are missing.
   - `/data/st-francis-csg-parcels.geojson` and `/data/kouga-zoning.geojson` are referenced but absent.

4. Demo parcels may be hidden by layer defaults.
   - Rich demo parcels are only clickable when `layers.parcels` is true and the `parcels-fill` layer is visible.
   - Public UI no longer exposes demo mode directly.

5. Official click targets can be visually thin or obscured.
   - CSG fill opacity is only 0.12, though fill layers are still clickable if present.
   - If the active layer has empty geometry, the cursor/click handler will never fire.

6. Handler registration depends on layer existence after style load.
   - `ensureSetup()` guards on `parcels-fill`; style/source timing looks mostly handled, but all official click handlers are registered in a separate effect that assumes official layers already exist.

7. Mapbox token or WebGL failure.
   - Missing `VITE_MAPBOX_ACCESS_TOKEN` prevents map initialization.
   - WebGL-disabled devices show an error overlay.

8. The visible thing may be a basemap parcel, not an app layer.
   - Mapbox satellite/streets may show parcel-like boundaries, but only app-added GeoJSON layers are clickable.

9. Official data selection opens a different panel.
   - Clicking CSG/Kouga does not open the rich property detail tabs; it opens `OfficialParcelPanel`.

## 7. Why Property Detail Tabs May Not Work

There are several different "tab not working" failure modes:

1. The user clicked an official CSG/Kouga parcel.
   - Official parcels do not use `PropertyPanel`; they use `OfficialParcelPanel`.
   - The rich tabs exist only for demo `Property` records from `PROPERTIES`.

2. The selected id is not a demo id.
   - `getProperty(selectedId)` only resolves ids like `parcel-123`.
   - Official features have arbitrary provider properties and no mapping to demo ids.

3. Notes/Listings/Saved Links require auth for persistence.
   - Unauthenticated users can open tabs, but saving prompts sign-in or shows sign-in copy.

4. Supabase env vars missing.
   - The lazy Supabase client throws if URL/key are absent. Any tab importing and using Supabase can fail at runtime.

5. RLS/schema drift.
   - If migrations are not applied, `property_notes`, `property_listings`, `property_research_links`, or `report_orders` operations fail.

6. `ReportsTab` SG document button may never appear.
   - `PropertyPanel` calls `<ReportsTab parcelId summary />` without passing `sgDoc`, so SG document list shows as unavailable for demo properties.

7. Horizontal tab strip can hide later tabs.
   - The tab strip is overflow-x scroll with a right gradient. Users on small screens may not realize more tabs are offscreen.

8. Buttons that look functional are placeholders.
   - Compare/share in the panel header have no implemented handlers.
   - Paid reports are "coming soon" and only record interest.

## 8. Why Listing Search Is Limited

Listing search is intentionally not a live feed.

Current implementation:

- `SearchBar` searches only local generated `PROPERTIES`, limited to 8 results.
- `ListingsTab` builds external portal links and a copyable search phrase.
- Users manually open portals, search, and save listing URLs.
- Saved listings are user-entered records in `property_listings`.

Limitations:

- No Property24/Private Property/Pam Golding/Seeff/RE/MAX API integration.
- No scraping, no portal result ingestion, no live listing verification.
- No geospatial/listing match algorithm.
- No global search index.
- No server-side search endpoint.
- No autocomplete over official CSG/Kouga feature attributes.
- Search is constrained to the synthetic pilot dataset and current hardcoded fields.

This is mostly by design and compliance posture: the UI repeatedly states that ErfStop does not copy/store proprietary listing content from third-party sites.

## 9. Deployment Risks

1. Required environment variables
   - `VITE_MAPBOX_ACCESS_TOKEN`
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_PUBLISHABLE_KEY`
   - `SUPABASE_URL`
   - `SUPABASE_SERVICE_ROLE_KEY` for server/admin operations
   - Optional ArcGIS/Kouga endpoint variables if using enrichment paths

2. Supabase Edge Function deployment
   - `arcgis-public-proxy` must be deployed to the configured Supabase project.
   - The app posts to `${VITE_SUPABASE_URL}/functions/v1/arcgis-public-proxy`.

3. Missing static official GeoJSON files
   - Referenced official fallback files do not exist in `public/data`.

4. External ArcGIS availability
   - Direct fetches can fail from CORS, endpoint changes, rate limiting, TLS issues, or service downtime.

5. Public admin diagnostics
   - `/admin/public-data-debug` and `/admin/readiness` should be access-controlled before production.

6. Demo data may be mistaken for official data
   - The app labels demo data, but the split between official map mode and demo intelligence mode can confuse users.

7. Browser-only assumptions
   - Some code uses `window`/`localStorage`; most usage is in effects, but SSR routes must be kept cautious.

8. Encoding artifacts
   - Many files show mojibake for em dashes, ellipses, bullets, copyright symbols, and square-meter symbols. This can look unprofessional and may harm metadata.

9. Dependency/build volatility
   - TanStack Start, Nitro beta, Vite 7, React 19, Tailwind 4, and Lovable config are modern/fast-moving.

10. Legal/compliance
   - POPIA, provider license limits, valuation disclaimer requirements, deeds/report display rules, and listing portal terms need final legal review.

11. RLS and migrations
   - The application assumes all migrations are applied exactly. Missing migrations will break dashboard/tabs.

12. No automated deployment verification was run in this audit
   - This was a code inspection only. Build/lint/test/runtime checks should be run before release.

## 10. Top 20 Improvements

1. Unify official parcels and detail panels by creating a canonical parcel id model that maps official feature identifiers to app records.
2. Make official parcels open a richer detail panel, even if fields are partial and source-labelled.
3. Add access control to `/admin`, `/admin/readiness`, and `/admin/public-data-debug`.
4. Add the missing official static fallback files or remove the static fallback references until real files exist.
5. Surface demo mode clearly in non-production environments, or create a deliberate "Demo parcels" layer toggle.
6. Make the home search provider-aware: demo search, official feature search, and saved-property search should be separate modes or unified with source badges.
7. Replace local generated parcel data with a provider-backed normalized property store for production.
8. Add an official feature property normalizer for CSG/Kouga fields, including LPI/erf/portion/municipality fields.
9. Pass SG document context into `ReportsTab` where possible, including LPI/erf/portion from official CSG features.
10. Add explicit `user_id` filters to Supabase queries in tabs and managers, even where RLS already protects data.
11. Move report interests from `localStorage` into Supabase so dashboard counts are account-backed.
12. Fix `/dashboard` saved-property links to navigate to `/?parcel=<parcel_id>`.
13. Improve tab discoverability on mobile with icons, visible scroll affordances, or grouped tab sections.
14. Add integration tests for click flows: demo parcel click, CSG click, Kouga click, style switch, layer toggle, and property panel tab switching.
15. Add provider contract tests for public ArcGIS conversion and official data fallback behavior.
16. Add runtime health checks that verify Mapbox token, Supabase env, Edge Function reachability, and ArcGIS endpoint reachability.
17. Clean up mojibake/encoding artifacts across UI copy and metadata.
18. Add a server-side listing integration abstraction while preserving the current no-scraping compliance stance.
19. Improve deployment docs with exact env vars, Supabase migration/function deploy steps, and smoke-test checklist.
20. Clarify product modes in the UI: "Official public data" vs "Demo intelligence" vs "User saved research."

## Recommended Change Order

1. Protect admin routes.
2. Fix obvious UX breaks: dashboard parcel links, missing SG document context, tab discoverability.
3. Add production-readiness checks for env vars and Supabase/Edge Function status.
4. Decide the official-vs-demo product model and make it explicit in UI.
5. Build the official parcel normalization layer.
6. Add tests around map click and tab flows.
7. Replace or backfill synthetic demo intelligence with provider-backed production data.
